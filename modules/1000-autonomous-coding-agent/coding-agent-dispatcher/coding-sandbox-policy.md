# Cedar policy envelope for the coding sandbox — TODO

With Nitro Sandboxes, the access restrictions people expect from an "isolated" sandbox come
from a **Cedar policy envelope**, generated by the `eks-nitro-sandbox-genpolicy` tool and
attached to the sandbox Pod via the `sandbox.amazonaws.com/policy` annotation —
**not** from the RuntimeClass. **A pod with no envelope is permit-all** (the
Nitro Sandboxes default), so the envelope is what actually constrains what the
sandbox may do.

> **Status:** `eks-nitro-sandbox-genpolicy` was **not available on the build host** at
> migration time (`which eks-nitro-sandbox-genpolicy` → not found). The dispatcher
> therefore ships the sandbox Pod with **no** `sandbox.amazonaws.com/policy`
> annotation today (permit-all). This is acceptable for the preview validation —
> the security boundary that matters most here (the micro-VM kernel boundary +
> the egress-lock NetworkPolicy) is in force regardless — but the envelope
> **should be generated and attached before the lab ships**. The dispatcher
> leaves a clearly-marked TODO at the annotation site in `sandbox_runner.py`
> (`_pod_manifest`).

## What the coding agent legitimately needs

Unlike the *Agents using a sandbox* analysis sandbox (which only runs one fixed `python3 main.py`
and can be locked down hard), the coding agent **legitimately execs and writes**:
Claude Code spawns `git`, `node`, `pytest`, shells, editors. So the envelope must
be permissive about exec but should still:

- **allow exec** for the run command (or allow-list the entrypoint), because the
  dispatcher drives the run via `kubectl exec bash /work/run.sh`;
- **`--deny-imds`** — the sandbox never needs the node's instance metadata
  (169.254.169.254); denying it removes a credential-theft path;
- keep logs available (do **not** `--deny-logs`) — the streamed pod log is the
  run transcript the dispatcher reads back.

## Exact command to generate + attach the envelope

Run this on a host that has `eks-nitro-sandbox-genpolicy` (generate from the **Pod**
manifest — genpolicy rejects `kind: Sandbox`), then set the resulting gzip+base64
string as the `sandbox.amazonaws.com/policy` annotation in
`sandbox_runner.py::_pod_manifest`:

```bash
# 1. Render the sandbox Pod manifest genpolicy will read. It must be the SAME
#    shape the dispatcher creates (runtimeClassName: isolated-sandbox, the
#    sandbox container, /work mount). Example skeleton:
cat > /tmp/coding-sandbox-pod.yaml <<'EOF'
apiVersion: v1
kind: Pod
metadata:
  name: coding-sandbox
  namespace: agent-sandbox
spec:
  runtimeClassName: isolated-sandbox
  terminationGracePeriodSeconds: 0
  restartPolicy: Never
  automountServiceAccountToken: false
  overhead: { eks.amazonaws.com/nitro-sandbox: "1", memory: 256Mi }
  containers:
    - name: sandbox
      image: <ACCOUNT>.dkr.ecr.<REGION>.amazonaws.com/coding-runtime-sandbox:v4
      command: ["sleep", "1920"]
      workingDir: /work
      resources:
        requests: { cpu: "2", memory: 4Gi }
        limits: { ephemeral-storage: 8Gi }
      volumeMounts: [{ name: work, mountPath: /work }]
  volumes: [{ name: work, emptyDir: {} }]
EOF

# 2. Generate the Cedar envelope. Allow exec (the coding agent needs it), deny
#    IMDS, keep logs. --allow-exec-command-for-container hashes the resolved
#    argv (SHA-384) into an allow-list; the dispatcher's drive command is
#    `bash /work/run.sh`, so allow that on the `sandbox` container:
eks-nitro-sandbox-genpolicy \
  --deny-imds \
  --allow-exec-command-for-container "sandbox=bash /work/run.sh" \
  -f /tmp/coding-sandbox-pod.yaml \
  > /tmp/coding-sandbox.policy    # gzip+base64 of {admission_policy, runtime_policy, version}

# 3. Paste the contents of /tmp/coding-sandbox.policy into _pod_manifest's
#    metadata.annotations as:
#       "sandbox.amazonaws.com/policy": "<contents>"
```

### Caveats to verify when the tool is available
- The exec allow-list is a **SHA-384 hash of the fully-resolved argv** — if the
  dispatcher's drive command changes, regenerate the envelope.
- `--with-irsa` is documented but **absent from the shipped binary** (Nitro Sandboxes capabilities report
  §3); this sandbox uses no IRSA (`automountServiceAccountToken: false`), so that
  is moot here.
- Verify enforcement by observing a **denial** (e.g. an exec of a non-allowed
  command is refused) — an absent/misplaced envelope silently fails **open**.
